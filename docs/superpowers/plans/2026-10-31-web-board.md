# Web Board, Linear Links, and Browser Terminals: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the design's three parts as three independently mergeable steps:
1. A Claude Code hook that links Linear issues to the task.
2. A local web board of every herdr task, with agent recaps and live Linear status.
3. Live, typeable terminals for a task's tab in the browser.

**Architecture:**
- Everything lives in the existing `herdr-tasks` Go binary.
- **Part 1** adds a `claude-hook` command and a safe editor for `~/.claude/settings.json`.
- **Part 2** adds a detached `serve` process: one per machine, serving every running herdr session.
  - It reads herdr over the socket, and task state through `store`.
  - It writes only through `reconcile`.
  - It streams updates to a plain-JS page as `text/event-stream`. The page reads the stream with `fetch`, so it can send an auth header.
- **Part 3** adds per-tab streams of `pane.read` ANSI snapshots, rendered with vendored xterm.js. Keystrokes go back in order through `pane.send_text`, `pane.send_keys` and `pane.send_input`.

**Tech Stack:** Go 1.23 standard library (`net/http` with method and wildcard patterns, `embed`, `crypto/hmac`, `crypto/subtle`), the existing deps (BurntSushi/toml, charmbracelet/*), and vendored `@xterm/xterm@6.0.0` plus `@xterm/addon-unicode11@0.9.0` (UMD builds). No Node build step and no new Go modules.

**Spec:** `docs/superpowers/specs/2026-10-30-web-board-design.md`.

## Global Constraints

- **Branches.** Never commit to `main`.
  - Part 1 is committed on `linear-links`, created from `web-board`.
  - Part 2 is committed on `task-board`, created from `linear-links`.
  - Part 3 is committed on `board-terminals`, created from `task-board`.
  - Each part ends releasable, with its own version bump (0.6.0, 0.7.0, 0.8.0).
- **Go 1.23.** Run `go vet ./...` and `go test ./...` before every commit. `go vet` catches Go 1.24+ standard-library calls.
  - Don't use the `omitzero` JSON tag: Go 1.23 silently ignores it. Use pointers with `omitempty` for optional times.
  - When you change imports of an indirect module, run `go mod tidy` and commit `go.mod`/`go.sum` in the same commit.
- **CI.** CI runs on Linux with `CGO_ENABLED=0` cross builds for darwin/linux on amd64/arm64.
  - macOS-only code shells out to `/usr/bin/security` behind `runtime.GOOS`, through a package variable so tests run on Linux.
- **No new Go modules and no Node build step.** xterm.js is vendored as committed files under `internal/board/web/vendor/` with its MIT license.
- **Leave the user's live setup alone.** Their running herdr sessions run `bin/herdr-tasks` from this checkout.
  - Never run `make build`, `make link`, `sh scripts/build.sh`, `go build -o bin/...`, or `herdr-tasks setup`/`remove`/`serve`/`board` against the real home.
  - Never write to `~/.claude/settings.json`, `~/.config/herdr` or `~/.local/state/herdr`.
  - Never send input to the user's panes.
  - Tests use fakes, `t.TempDir()` and `t.Setenv` (`HOME`, `HERDR_PLUGIN_STATE_DIR`, `HERDR_PLUGIN_CONFIG_DIR`, `CLAUDE_CONFIG_DIR`).
  - Daemon tests listen on `127.0.0.1:0` to get a free port (never 7391), and stop every spawned helper in `t.Cleanup`.
- **Test data is made up.** The repo is public. Use an invented org (`acme`), invented IDs (`ABC-12`), and invented titles. Never copy anything from `~/.claude/projects` or live herdr into the repo.
- **Settings are off by default.** In `~/.config/herdr/plugins/config/herdr-tasks/config.toml`:
  - `board = false`
  - `board_port = 7391` (0 or unset means 7391)
  - `linear_hook = false`
- **Board security** (replaces the spec's cookie idea, because cookies are shared across ports on `127.0.0.1`):
  - **Listening.** Listen on `127.0.0.1:<port>` only. Every request's `Host` must be `127.0.0.1:<port>` or `localhost:<port>`; otherwise 403.
  - **Static files.** `/` and `/static/*` need no credential. They hold no data. Every response carries:
    - `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'`
    - `X-Frame-Options: DENY`
    - `Referrer-Policy: no-referrer`
    - `Cache-Control: no-store`
  - **API.** Every `/api/*` request needs `Authorization: Bearer <secret>`:
    - The **admin token** is 32 random bytes as hex, stored in `<stateDir>/board-token` with mode 0600. The CLI uses it. It's the only credential for `/api/login-code` and `/api/shutdown`.
    - The **browser key** is `hex(HMAC-SHA256(token, "herdr-tasks board browser\x00" + run))`, where `run` is 32 random bytes `NewAuth` makes as the server starts. It works for everything else, with that run of the server only. (Changed in review: a key a page left open sends to whatever has the port while no server runs is no use to the next server.)
    - Compare with `crypto/subtle.ConstantTimeCompare`.
    - A missing or wrong secret gets 401 JSON `{"error":"Sign in again: run herdr-tasks board, or use Open task board in herdr."}`.
  - **Request headers.** Reject (403) any `/api/*` request whose `Origin` header is present and isn't `http://127.0.0.1:<port>` or `http://localhost:<port>`. Also reject any whose `Sec-Fetch-Site` is `cross-site` or `same-site`.
  - **Sign-in.** The CLI asks for a one-time code: single use, valid 60 s. It opens `http://127.0.0.1:<port>/?code=<code>`.
    - The page posts the code to `POST /api/session`, which needs no credential (the code is the credential). It gets `{"key": <browser key>}` back.
    - The page keeps the key in `localStorage` (origin-scoped, so other ports can't read it). It falls back to memory when storage throws.
    - Then it calls `history.replaceState` to the clean URL.
    - Never log codes, keys or tokens.
  - **Token rotation.** Rotating the token (`board --new-token`) runs `Stop` with the old token, then writes the new token, then `Ensure`. Old browser keys stop working, as they do whenever the server restarts.
- **State files are yours only** (added in review). The store creates the state dir 0700 and chmods an existing one to 0700, opens `<session>.lock` 0600, and saves `<session>.json` through `os.CreateTemp` (0600) and a rename, so a file an older version left 0644 is replaced on its next save. Notes and artifact links with their `sk` share key live there. Pinned by `TestStateIsYoursOnly`.
- **Untrusted content.** Titles, notes, log entries, link labels, agent titles, recaps, prompts, replies and Linear fields come from agents and other people.
  - The page builds DOM only with `textContent`, `setAttribute` and `createElement`. Never use `innerHTML`, `outerHTML`, `insertAdjacentHTML` or `document.write`.
  - Only `http:` and `https:` URLs become links, with `rel="noopener noreferrer"` and `target="_blank"`. Anything else is shown as text.
- **The Claude hook stays silent.** `herdr-tasks claude-hook` prints nothing and always exits 0, within 5 s at most: an internal deadline gives up and exits.
  - Errors go to `<stateDir>/claude-hook.log`, which is truncated when it passes 256 KB.
  - It never calls `reconcile.Run` and never writes to herdr. It edits the state file through `store` only. (This deliberately narrows the spec's "existing logic": a link changes nothing herdr shows, and a full sync could rearrange panes under Claude.)
- **The board server process:**
  - Keeps its lock, `board.json` and log in `<stateDir>/board/`, not in `<stateDir>` itself: the store keeps each session's tasks there as `<session>.json` and `<session>.lock`, and a herdr session may be called `board`. (Added in review.)
  - Starts with `Setsid`. stdio goes to `<stateDir>/board/board.log`, opened for append; stdin is `/dev/null`. It never inherits herdr's pipes.
  - Runs single-instance through a flock on `<stateDir>/board/board.lock`, which the server keeps referenced for its whole life.
  - Writes `<stateDir>/board/board.json` `{pid, port, version, build, exe}` (0600) once it's listening. `build` is the executable's `size-mtimeUnixNano`.
  - `Stop` and `Health` use the recorded port.
- **Server concurrency:**
  - One server-wide context is cancelled on shutdown. Every stream handler, poller and subscription selects on it.
  - Shutdown is `http.Server.Shutdown` with a 2 s context, then `Close`.
  - `WriteTimeout` is 0 and `ReadHeaderTimeout` is 10 s.
  - Each session's herdr and store reads run in that session's own goroutine, with timeouts, and publish an immutable snapshot. One wedged session leaves the last good snapshot in place and never blocks the others.
  - One builder goroutine is fed by a coalescing (cap-1) trigger. It publishes the latest board atomically. `GET /api/board` returns the published board and never builds one.
  - Each stream subscriber has a cap-1, latest-wins queue, so a slow browser never blocks anything.
- **Visible strings follow the repo's tone:** short and plain. CLI messages are prefixed `herdr-tasks:`.

## Review Focus

These are the inputs most likely to hurt a user without a main test noticing. Each line names the test that pins it.

1. **An unusual settings.json.** JSONC, a symlink (dotfile managers), another tool's hooks, a concurrent edit. Expected: unparseable files are left untouched, with a note. The symlink target is edited in place and the link stays a link. Only our handler is removed. A file that changed while we worked is not clobbered. Pinned by `TestApplyRefusesJSONC` and `TestRemoveKeepsOtherHooksInAMixedGroup` (Task 4), and by `TestWriteSettingsFollowsSymlink` and `TestWriteSettingsRefusesAConcurrentChange` (Task 4).
2. **A burst of Linear calls, or a held state lock.** Claude reads dozens of issues, or a strip holds the store lock. Expected: at most one link per issue, dismissed issues stay out, and the hook exits within 5 s whatever happens. Pinned by `TestAutoLinkIsIdempotentAcrossURLForms` (Task 2) and `TestClaudeHookGivesUpAtTheDeadline` (Task 5).
3. **Restarts with the board open.** A rebuild, a version change, a port change, or `--new-token` while a browser has the board open. Expected: the old server stops within about 3 s, a new one starts, and no false "port taken" message appears. Pinned by `TestStopEndsServerWithOpenStream`, `TestEnsureReplacesAnOtherBuild`, `TestPortChangeStopsTheOldServer` and `TestNewTokenRotation` (Task 11).
4. **Hostile web pages and hostile content.** Another site posting to the API, another localhost port, or a task title like `<img onerror=…>` or a `javascript:` link. Expected: 401 or 403 and nothing typed; titles are shown as text; the link isn't clickable. Pinned by `TestAPIWithoutKeyIs401`, `TestForeignOriginIs403` and `TestCrossSiteFetchIs403` (Task 11), and `TestWebAssetsAvoidHTMLInjection` (Task 14).
5. **Large, odd, or growing Claude logs.** A 300 MB log, missing fields, a truncated last line, or constant appends. Expected: bounded reads, and only appended bytes re-read. Pinned by `TestReadStopsAtCap`, `TestReadSkipsTruncatedLastLine` and `TestCacheReadsOnlyTheAppendedBytes` (Task 8).

  // Payload is the part of Claude Code's PostToolUse hook input this uses.
  type Payload struct {
      ToolName     string          `json:"tool_name"`
      ToolInput    json.RawMessage `json:"tool_input"`
      ToolResponse json.RawMessage `json:"tool_response"`
  }
  // Issue is a Linear issue a tool call worked on. URL is "" when only the ID is known.
  type Issue struct{ ID, URL string }
  const Matcher = `^mcp__.*[Ll]inear.*__(get_issue|save_issue|save_comment|create_attachment|create_attachment_from_upload)$`

- Rules for `Find`:
  1. The tool name must match `Matcher`.
  2. **`get_issue` and `save_issue`:**
     - Decode `tool_response` as `[]struct{Type, Text string}`, then the first item's `Text` as `{id, url}`.

  3. **`save_comment`:** the input's `issueId`, if it matches the ID pattern. Edits (`id` without `issueId`) give nothing.
  4. **`create_attachment` and `create_attachment_from_upload`:** the input's `issue`, if it matches the ID pattern.
  5. Never scan text for URLs.

**Files:**

**Interfaces:**
- Produces:
  ```go
  func SettingsPath() string          // $CLAUDE_CONFIG_DIR/settings.json, else ~/.claude/settings.json
  func Command(bin string) string     // `"<bin>" claude-hook`, e.g. `"$HOME/.local/bin/herdr-tasks" claude-hook`
  func Apply(src []byte, command string) ([]byte, error) // add our hook or update its command; other bytes kept where possible
  func Remove(src []byte) ([]byte, error)                 // take ours out; empty groups and an empty PostToolUse go too
  // WriteSettings edits the settings file safely: it follows symlinks (editing the target), serializes our own writers with
  // a flock on <lockDir>/claude-settings.lock, writes a unique temp file in the target's directory, keeps the file mode,
  // makes a one-time backup <target>.before-herdr-tasks, and refuses (error) when the file changed between read and rename.
  // When it's saved again while the first change is put back, the newest version stays in place and the one before it is
  // kept next to it; no outside save is deleted. A file still empty a moment after it was emptied (changed under 2 s ago)
  // is refused too, before any backup: a save is probably under way, and the swap couldn't tell it from an empty file.
  // It returns changed=false and writes nothing when edit returns the same bytes, or when the file doesn't exist and create is false.
  func WriteSettings(path, lockDir string, create bool, edit func([]byte) ([]byte, error)) (changed bool, err error)
  ```
- **Our handler.** In this key order: `{"type":"command","command":<Command(bin)>,"timeout":10,"async":true}`, in a group `{"matcher":Matcher,"hooks":[handler]}`.
  - A handler is ours if its whole `command` is one shell word naming a file called exactly `herdr-tasks` (bare, single- or double-quoted, with or without a directory), then `claude-hook`: `^\s*(?:"(?:(?:[^"\\]|\\.)*/)?herdr-tasks"|'(?:[^']*/)?herdr-tasks'|(?:[^\s"'\\]*/)?herdr-tasks)\s+claude-hook\s*$`. So `echo herdr-tasks claude-hook` and `/opt/acme/not-herdr-tasks claude-hook` aren't ours.
- **Editing.** Splice the top-level `"hooks"` value by byte offsets (`json.Decoder.Token` and `InputOffset`) and render it with `json.Indent` at a 2-space indent, as the prototype does.
  - Never round-trip the whole file through `map[string]any`, and never let `json.Marshal` HTML-escape (`&` stays `&`).
  - An empty `src` becomes `{\n  "hooks": {…}\n}\n` on Apply and stays empty on Remove.
  - Input that isn't strict JSON gives an error.
- **Wiring:**
  - `setup()` (unless `--no-config`): `WriteSettings(SettingsPath(), store.Dir(), opts.LinearHook, Apply-or-Remove)`, where `command` comes from `setup.InstallBinary`.
    - When `~/.local/bin/herdr-tasks` isn't ours, `InstallBinary` doesn't return the build path, which herdr's temporary build folder takes away: it copies the binary to `<stateDir>/bin/herdr-tasks` (temp + rename) and returns that, and `RemoveBinary` deletes it. A file on PATH is ours when it's missing, named by the `installed-binary` marker, or a link an older version made: one that points nowhere now, or at the binary being installed. A link to any other file is yours and is left alone (changed in review). Pinned by `TestInstallBinaryKeepsItsOwnCopyWhenPathIsTaken`, `TestInstallBinaryLeavesYourSymlinkAlone`, `TestRemoveBinaryLeavesYourSymlinkAlone` and `TestInstallBinaryReplacesALegacyLink`.
    - It prints `herdr-tasks: added the Linear hook to <path>` or `herdr-tasks: took the Linear hook out of <path>` when changed.
    - Errors become notes: `your Claude settings don't parse, so the Linear hook wasn't changed`, or the error text.
  - `remove()`: always calls `WriteSettings(..., false, Remove)`, right after `board.Stop` and before anything else changes. Settings that don't parse are a note, as Claude Code can't run a hook from them either. Any other error, such as an edit conflict, stops `remove` there, so the binary is still there to run it again (changed in review).

  - **One poller per (session, tab)**, shared by every viewer. It is created on the first viewer and closed 5 s after the last one leaves.
  - **Layout**, every 1 s:
    - Panes come from `Panes()` filtered to the tab, leaving out `Label == "Task strip"`, with rects from `TabLayout`.

  - **Queues:** each subscriber's queue is bounded and latest-wins per pane, plus one for the layout.
  - **Pane check:** the poller keeps a pane→tab map, used by the input endpoint.
- **`POST /api/pane/input`** with `{"session","pane","ops":[{"text":…}|{"keys":[…]}|{"paste":…}]}`, 1–64 ops, at most 64 KiB in total:
  - The pane must be in the poller's map for a task tab and must not be a strip. Otherwise 403. If no poller is watching the tab, look it up with `Panes()` once.
  - Ops are applied in order, under a per-pane mutex, so concurrent requests can't interleave.
  - Answers 204. If an op fails, the rest are dropped and the answer is 502 with `{"error":<herdr message>,"applied":n}`.

  - Matches are taken in order of appearance:
    - **Slack:** `https://([a-z0-9-]+\.)+slack\.com/archives/<ID>`, with an optional `/p<16 digits>`. Keep only the `thread_ts` and `cid` query parameters.

    - **Hosted:** `https://` URLs whose host is on the static-host list.
    - **Local:** `http(s)://` to `localhost`, `127.0.0.1` or `[::1]`, with an optional port, path, query and fragment.
    - **Files:**
      - `file://` URLs.
      - Path-shaped tokens ending `.html`/`.htm` (case-insensitive). Path-shaped means absolute, or starting with `~/`, `./` or `../`, or containing `/`.
      - Tokens are delimited by whitespace or brackets. A token inside backticks, quotes, or a Markdown link destination may contain spaces.
      - `~/` is the home directory. A relative token resolves against `Cwd`.
  - **Trimming.** Trailing `.,;:!?'"*` and backticks are trimmed. A trailing `)` or `]` is trimmed only when it's unbalanced within the match, so `http://[::1]` and `/a(1).html` survive. `_` is never trimmed.

    - no `template` or `.tpl.` in the base name;

  - **Explicit pages** (paths in your prompt, `file://` URLs, and navigate) skip those three extra checks.
  - A path in a reply is implicit because Claude's replies name the files it edited (`src/index.html`, `templates/base.html`), which the Write checks already skipped. A `file://` URL in a reply stays explicit.

  **4. Skipping local and hosted links that may carry secrets**
  - A link is skipped when it has userinfo (`user:pass@`).
  - It's skipped when a percent-decoded query or fragment parameter name contains (case-insensitive) `token`, `code`, `key`, `secret`, `pass`, `auth`, `sig`, `session` or `jwt`.

  - It's skipped when the path, or a hash route, contains `/callback` or `/oauth` once percent-decoded, as a router reads it (`#/%63allback` is `/callback`).
  - Any link that isn't `task.SafeURL` is skipped.

  **5. Titles:** the first `<title>…</title>` in the first 64 KiB, run through `html.UnescapeString`, then `task.CleanLabel`.
